## 2. Options compared
| | **A. AGP screenshot test suites** (Compose Preview Screenshot Testing on AGP test suites) | **B. Roborazzi + Robolectric** |
|---|---|---|
| Status | Experimental ("APIs and DSL syntax are subject to change"). The standalone plugin `com.android.compose.screenshot` is deprecated; Google points to test suites on AGP 9.5+ | Mature third-party (takahirom), 1.79.0 (2026-11-12), very active |
| Coordinates | No new plugin (uses `com.android.application`). Engine `0.0.1-alpha16`. Suite deps: `com.android.tools.screenshot:screenshot-validation-api:0.0.1-alpha16` + `libs.androidx.compose.ui.tooling` | Plugin `io.github.takahirom.roborazzi` 1.79.0; `io.github.takahirom.roborazzi:roborazzi`, `roborazzi-compose`, `roborazzi-junit-rule`; `org.robolectric:robolectric:4.18.1`; `ui-test-junit4` for tests. Optional: `roborazzi-compose-preview-scanner-support` + ComposablePreviewScanner (0.9.0+) |
| Flags | `gradle.properties`: `android.experimental.enableScreenshotTest=true`, `android.experimental.testSuiteSupport=true` | `testOptions.unitTests.isIncludeAndroidResources = true`; `@GraphicsMode(NATIVE)` on tests |
| Robolectric | No | Yes (4.18.1 supports SDK 36/37, so it matches compileSdk 37) |
| Renderer | Host JVM, Layoutlib (the Android Studio Preview renderer) | Host JVM, Robolectric Native Graphics |
| What it captures | Only functions with `@PreviewTest` + `@Preview` in `src/screenshotTest/kotlin/` | Any composable in a JUnit test (`captureRoboImage`), or scanned previews |
| Theme / fontScale / locale control | Through `@Preview(uiMode = ..., fontScale = 2f, locale = "en", widthDp, heightDp, device = "spec:...,dpi=420")`. The docs **do not state** that these are honoured; Layoutlib honours them in Studio Preview. Verify in the pilot | Full programmatic control: `RuntimeEnvironment.setQualifiers("+en-night")`, `RuntimeEnvironment.setFontScale(2f)`, `@Config(qualifiers = "w380dp-h800dp-420dpi")` |
| Animations | Renders the first composition. **Not documented.** `entrance()` would render invisible (alpha 0) unless it skips when `LocalInspectionMode.current` is true | `composeTestRule.mainClock` can advance to the end state; no code change needed |
| File names | Generated by the tool from the preview function and preview name. Custom names like `<subject>_<theme>_<locale>_fs<scale>.png` are **not** directly controllable; encode them in the preview function/`name` | Fully controllable (`captureRoboImage("S1_light_fr_fs1.0.png")`) |
| Baselines | Committed in `app/src/screenshotTest{Target}{Variant}/reference/` (exact folder from the docs' pattern `{suite}{Target}{Variant}`) | Default `build/outputs/roborazzi` (not committed); set `roborazzi.outputDir` to e.g. `app/src/screenshots` |
| Record / verify | Docs example (variant `demoDebug`): `updateScreenshotTestDefaultDemoDebugTestSuite` / `testScreenshotTestDefaultDemoDebugTestSuite`. For us, inferred and unverified: `.\gradlew.bat updateScreenshotTestDefaultDebugTestSuite` / `testScreenshotTestDefaultDebugTestSuite` | `.\gradlew.bat recordRoborazziDebug` / `verifyRoborazziDebug` (`compareRoborazziDebug` for a diff report) |
| Tolerance | `imageDifferenceThreshold` exists (release notes alpha06/alpha10); support in the suite DSL is **not stated** | Configurable (`RoborazziOptions.CompareOptions(changeThreshold = ...)`) |
| Config cache | Advertised as fully supported | Fixed in Roborazzi 1.77.0 |
| Windows | Command-line-length bug fixed in alpha14 | Works; FAQ says images differ across macOS, Linux and Windows, so record and verify on one OS |
| AGP 9.5.2 stable | Docs say "AGP 9.5.0-alpha03 or higher"; stable is not mentioned explicitly but is higher | AGP 9 / built-in Kotlin compatibility **not stated** by Roborazzi |
| Footprint | 2 flags + 1 `testOptions` block + 2 suite-scoped deps; no new plugin; nothing in the app APK | 1 plugin + 3-4 artifacts + Robolectric (large: downloads an android-all jar per SDK, about 100+ MB first run) + `ui-test-junit4` in `testImplementation` |

| 20 images | One `@Preview` per image (or a multipreview annotation per axis); about 20 small functions | One parameterised test |

## 4. Recommendation
**Option A, AGP screenshot test suites**, as a time-boxed pilot, with Roborazzi as the fallback.
- It is the smallest setup: no new plugin, no Robolectric, nothing new in the app. It uses the AGP version we already have and the renderer the team already sees in Studio Preview.
- Google's current direction: the standalone plugin is deprecated in favour of test suites on AGP 9.5+.
- Costs to accept: it is experimental (DSL may change); file names are tool-generated; and `entrance()` needs a `LocalInspectionMode` guard (a 2-line change, useful on its own).

**Pilot gate.** Stop and switch to Roborazzi if any of these fails on AGP 9.5.2 stable:
1. The suite configures with configuration cache on.
2. `update...` writes references for S1.
3. `@Preview(locale = "en", fontScale = 2f, uiMode = night)` visibly changes the image.

Do not try to fix the AGP option beyond about half a day.

### Smallest setup for feature-engineer (from the official docs; adjust names after a dry run)
- `gradle.properties`: add `android.experimental.enableScreenshotTest=true` and `android.experimental.testSuiteSupport=true`.
- `app/build.gradle.kts`, inside `android { testOptions { ... } }`: `screenshotTests.create("screenshotTest") { engineVersion = "0.0.1-alpha16"; targetVariants.add("debug"); dependencies { implementation(libs.androidx.compose.ui.tooling); implementation("com.android.tools.screenshot:screenshot-validation-api:0.0.1-alpha16") } }`. Prefer a catalog entry for the validation API.
  - Risk: the suite `dependencies` block may need `implementation(platform(libs.androidx.compose.bom))` for `ui-tooling` to get a version, the same template trap as the androidTest BOM fix in CLAUDE.md section 8.
- Tests go in `app/src/screenshotTest/kotlin/com/example/hackapp/screenshots/`, one file per subject, each preview annotated `@PreviewTest` + `@Preview(name = "S1_light_fr_fs1.0", ...)`.
  - `PreviewDefaults` is `internal` in `main`; check that the suite source set can see it. If not, repeat the constants.
- Code: guard `Modifier.entrance()` (and the scale-in helper below it) with `LocalInspectionMode.current`.
- Run (workflow-auditor only during audits): `.\gradlew.bat tasks --all | Select-String ScreenshotTest` to find the real task names. Then use `update...` to record and `test...` to verify. Record baselines only after the M1 fixes (visual-designer).
- Commit the `reference/` folder. Record and verify on Windows only; there is no CI yet.

### Determinism notes (both options)
- Fonts: `HackappFonts` are `FontFamily.Default`. Layoutlib/Robolectric use their own bundled Roboto, so images will not match a device pixel-for-pixel. Bundling Figtree (CLAUDE.md open item 6) will change every baseline: do it before recording, or plan one re-record.
- Use fixed sample data in previews (no `LocalDate.now()`, no DataStore).
- Keep one OS for record and verify.
